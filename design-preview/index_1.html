Easing is the personality

The same 300ms move reads as cheap, smooth, or playful depending only on the curve. Pick the curve by intent, never by habit.
Preview · tap a curve
Rule: linear only for spinners. Everything that moves in response to a human starts fast and settles slow (easeOut). Back/elastic curves are reserved for the 2–3 delightful moments per flow — overused, they feel like a toy.

One conductor per transition

When several things animate at once with no leader, the eye doesn't know where to land. Let one element lead (the thing you touched), and let the rest follow 60ms behind.

What reduced motion actually keeps

Reduced motion doesn't mean a dead interface — it means replacing spatial movement with fades and state changes. Design both versions deliberately instead of letting motion break for some users.
Preview · motion vs reduce-motion
Full motion
slides, springs, stagger
Reduced
instant fades only
Rule: under reduce-motion keep opacity changes and state swaps (they carry meaning), drop all spatial movement (slide, scale, parallax, stagger). Your FixPressable, FixPulse and FixScaleIn already branch on MediaQuery.disableAnimations — the job is extending that guard to every new animation.

Haptics, sound & the QA checklist

Motion without the other senses is half a design. Haptics should mark decisions, not decoration — and every animation ships with the same five checks.
Pairing table
Nav select → selectionClick (already in FixBottomNavigation)
Provider accepted → light impact once, with the burst
Cancel / destructive → warning tick, never success haptic
Status change → optional soft tick (sound stays off by default)
QA checklist · every animation ships with these
  • Runs at 60fps on a low-end Android device (profile with flutter run --profile)
  • Interruptible: a new gesture cancels the in-flight animation
  • No layout shift: animation moves paint, not layout
  • Degrades to a fade under disableAnimations
  • Never delays an action, never animates data that isn't live
