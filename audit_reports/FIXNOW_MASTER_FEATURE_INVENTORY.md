# FixNow — Master Feature Inventory & Hierarchy

**Audit Date:** 2026-10-13  
**Audit Scope:** Repository-Wide Source Audit (`mobile/`, `admin/`, `backend/`, `shared/`, `e2e/`, `infrastructure/`, `scripts/`)  
**Commit Baseline:** `d9951c4` + Phase 1 Remediation (`seed.js`, `scan-secrets.mjs`, `catalog-seed.spec.ts`)  
**Status Taxonomy:**
- `IMPLEMENTED_EVIDENCED`: Code exists and verified by passing test execution or runtime check.
- `IMPLEMENTED_UNVERIFIED`: Code exists, but unexecuted or lacking dedicated automated test.
- `PARTIAL`: Incomplete implementation or disconnected paths.
- `UI_ONLY`: Interface element exists without complete backend backing.
- `BACKEND_ONLY`: Backend API exists without customer/provider/admin client implementation.
- `MOCKED_SIMULATED`: Uses dummy stubs, simulated delays, or synthetic in-memory state.
- `BROKEN`: Code contains proven logic error, runtime exception, or unreachable route.
- `UNWIRED`: Component or repository exists but is never instantiated or invoked in the live flow.
- `DEAD_UNREACHABLE`: Orphaned file, screen, or route with no valid navigation/import path.

---

## 1. Feature Hierarchy Architecture

The system features are structured across five levels:
- **Level 1 — Module:** Major business capability (e.g., Identity & Access, Service Catalog, Booking Lifecycle, Realtime & Location, Payments & Financials, Trust & Safety, Emergency Dispatch, Admin Operations, Advisory AI).
- **Level 2 — Feature:** User-visible or major system capability (e.g., Customer Authentication, Service Start Verification, Push Notification Delivery).
- **Level 3 — Sub-feature:** Specific functional component (e.g., Email OTP Verification, Service Start OTP Generation, Dynamic Radius Calculation).
- **Level 4 — Micro-feature:** Individual control, user interaction, field validation, or conditional visual state (e.g., OTP Resend Cooldown Countdown, Single-Flight Refresh Lock, Simulated Photo Injection).
- **Level 5 — Technical Behavior:** Low-level engineering implementation (e.g., HMAC-SHA256 derivation, `pessimistic_write` lock, optimistic `@VersionColumn` CAS, Redis pub/sub fanout, ClamAV streaming check).

## 6. Detailed Feature Inventory by Category & Identifier

### Section 6.1 — Identity, Access & User Management (CUS-AUTH / PRO-REG / ADM-AUTH / API-AUTH)
- `CUS-AUTH-001` (Customer Registration): Level 4 controls include email field, password toggle, password confirmation matching, submit button with loading spinner. Validation enforces RFC 5322 email syntax and minimum 12-character passwords.
- `CUS-AUTH-002` (Customer Login): Email/password fields with remember-me preference; lockout alert dialog after 5 consecutive failed attempts (15-minute freeze).
- `CUS-AUTH-003` (OTP Verification): Pin code entry auto-advancing across cells; paste-clipboard support; countdown resend timer.
- `CUS-AUTH-004` (Biometric Quick Login): Local toggle switch in verification UI; inert placeholder lacking native biometric bridge.
- `CUS-AUTH-005` (Token Lifecycle & Refresh): Transparent interceptor in `api_client.dart`; on 401 response executes single-flight queue; rotates refresh token on success; forces logout on revocation.
- `PRO-REG-001` (Provider Registration): Dual-segmented control on welcome screen routes to provider registration flow, creating unverified applicant user record.
- `ADM-AUTH-001` (Admin Staff Login): Dedicated admin login form; sets httpOnly strict sameSite session cookies; rejects accounts without staff role assignments.

### Section 6.2 — Service Discovery & Catalog (CUS-CAT / ADM-CAT / API-CAT)
- `CUS-CAT-001` (Active Category Browsing): Pull-to-refresh; shimmer skeleton loading; offline saved-data banner indicating timestamp of cached data.
- `CUS-CAT-002` (Live Search & Filter): Instant regex search matching title and keywords; filter chips for emergency, budget tiers, and rating rank.
- `CUS-CAT-003` (Sub-Service Catalog): Multi-item cart stepper; sticky bottom bar showing total item count and currency amount; expandable cart sheet.
- `CUS-CAT-004` (Book-Again Carousel): Queries customer's past completed jobs; one-tap re-booking drawer.
- `ADM-CAT-001` (Category Administration): Form to create new category, configure slug, upload icon reference, assign emergency flag, and set starting price.

### Section 6.3 — Booking Lifecycle & Operations (CUS-BOK / PRO-JOB / ADM-BOK / API-BOK)
- `CUS-BOK-001` (Booking Creation): Address selector modal, date-time schedule sheet, special instructions text field, dynamic price quote display.
- `CUS-BOK-002` (Price Resolution & GST): Enforces authoritative backend price resolution from `sub_services`; adds statutory 18% GST.
- `CUS-BOK-004` (Booking Dossier & Real-Time Tracking): Multi-stage timeline stepper (Requested -> Assigned -> En Route -> In Progress -> Completed); provider details card with telephone and chat triggers.
- `CUS-BOK-005` (Cancellation): Cancellation confirmation modal requiring structured reason selection; applies cancellation fee policies if provider is en route.
- `CUS-BOK-007` (Service Start Security OTP): Secure 4-digit code generated deterministically from secret and booking UUID; displayed to customer on arrival.
- `PRO-JOB-002` (Provider Atomic Claim): Concurrency claim guarded by version check; rejects with 409 conflict if another technician claims first.
- `PRO-ACT-002` (Technician OTP Validation): 4-digit code entry in cockpit; validated against backend using `timingSafeEqual` before state moves to `IN_PROGRESS`.
- `PRO-ACT-003` (Job Proof Photos): Camera modal allowing technician to capture before/after work evidence; uploads directly to quarantine bucket.

### Section 6.4 — Realtime, Telemetry & Chat (CUS-TRK / PRO-LOC / API-RT)
- `CUS-TRK-001` (Live GPS Map Tracking): Map widget rendering technician location updates received via WebSocket; shows estimated road route and arrival time.
- `CUS-TRK-002` (Active Booking Island): Floating top bar widget displaying current active booking status and countdown across all app tabs.
- `CUS-CHAT-001` (In-Booking Messaging): Chat bubble feed; auto-scroll to bottom; delivery checkmarks; WebSocket frame transport with 3s polling fallback.
- `PRO-LOC-001` (Provider Location Broadcast): Geolocation listener broadcasting coordinates every 10 seconds or 50 meters; rate-limited by backend configurable throttle.

### Section 6.5 — Payments, Guarantees & Invoicing (CUS-PAY / PRO-EAR / ADM-GUA / API-PAY)
- `CUS-PAY-001` (Tax Invoice PDF): Renders complete tax breakdown, customer address, statutory GSTIN, SAC codes, and download/share actions.
- `CUS-PAY-002` (Payment Checkout): Payment method selector supporting UPI, NetBanking, Debit/Credit cards; integrates Razorpay SDK.
- `PRO-EAR-001` (Provider Earnings Ledger): Summary of completed jobs, platform commission deduction (20%), and weekly settlement status.
- `CUS-GUA-001` (Service Guarantee Claim): Form to report unsatisfactory service within 30-day window; upload photos; request free re-service.

### Section 6.6 — Emergency Dispatch (CUS-EMG / ADM-EMG / API-EMG)
- `CUS-EMG-001` (Emergency SOS Dispatch): High-visibility emergency button requiring 3-second hold to avoid accidental triggers; initiates automated wave dispatch to all providers within 15 km.

### Section 6.7 — Multimodal Advisory AI (CUS-AI / API-AI)

- `CUS-AI-002` (Advisory Price Estimation): Calculates median price based on past similar jobs; provides high/medium/low confidence score.

### Section 6.8 — Support & Dispute Adjudication (CUS-SUP / ADM-SUP / API-SUP)
